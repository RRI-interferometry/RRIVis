## 1. Overview

**friendlyVRI** ("The Friendly Virtual Radio Interferometer", abbreviated
**fVRI** in its own documentation) is a small, self-contained desktop
application that simulates astronomical observations made with linked
arrays of radio antennas using *earth-rotation aperture synthesis*. It is
explicitly positioned as the Python successor to the original Java-based
"VRI" tool by Nuria McKay, Derek McKay and Mark Wieringa
(`docs/ABOUT.txt`, `README.md` lines 3–9).

The package is intentionally educational and "quick-look": it ignores
non-coplanar baselines, time averaging, multi-frequency synthesis, noise,
sensitivity, polarisation, primary-beam shape, deconvolution and spectral
imaging. The README explicitly states that anyone needing a robust
simulation should reach for CASA, MIRIAD or AIPS instead
(`README.md` lines 70–80, `docs/ABOUT.txt` lines 53–62).

The project is composed of:

* a **Tkinter GUI front-end** (two scripts, `vriTk.py` and
  `vriTkDemo.py`) that drives interaction, plotting, and a webcam-based
  "scan-an-array-from-paper" gimmick.
* a **headless calculation back-end** in `Imports/vriCalc.py` that
  exposes `observationManager` and `antArray` and can be used directly
  from an iPython/Jupyter shell.
* a **library of 79 telescope configuration files** in `arrays/`
  (VLA, ATCA, ALMA Cycle 1 + Cycle 6 + ACA, ASKAP, MeerKAT, MWA, GMRT,
  PdBI/PDB, SMA, WSRT).
* a **library of demo model images** (`models/*.png`,
  `models/*.jpg`) used as toy "skies".

### 2.1 Per-folder commentary

* **`arrays/`** — Plain ASCII config files (one per array configuration,
  extension `.config`). Read on application start by
  `observationManager._load_all_arrays()` via `glob.glob("arrays/*.config")`
  (`Imports/vriCalc.py` lines 232–243). The format is documented in §6.1.
  The companion file `ALMA_config.md` notes that the ALMA Cycle-6 layouts
  were sourced from `https://almascience.nrao.edu/tools/casa-simulator`.
* **`Imports/`** — Despite the directory name being capitalised
  (un-Pythonic), it is a regular package thanks to its `__init__.py`
  with `__all__ = ['util_tk', 'vriCalc']` (`Imports/__init__.py`).
  `util_scan.py` is *not* listed in `__all__` but is imported with a
  star-import by both GUI scripts via
  `from Imports.util_scan import *` (`vriTk.py` line 124,
  `vriTkDemo.py` line 143). The `*.gif` / `*.png` files here are GUI
  icons (folder browse button, camera capture button) loaded by
  `tk.PhotoImage(file='Imports/folder_small.gif')` (`vriTk.py` line 1095)
  and similarly for the webcam icon when `cv2` is importable
  (`vriTk.py` lines 1102–1107).
* **`models/`** — Raster images ingested through
  `PIL.Image.open(...).convert("L")` and flipped with `np.flipud`
  before being stored as a 2-D `numpy` array
  (`Imports/vriCalc.py` lines 519–524). They are interpreted as
  intensity skies (Stokes I only); colour information is discarded.
* **`docs/`** — Static text files used both as on-disk documentation and
  as the *runtime* content of the GUI's Help → Instructions/About menu
  items, served via `_show_textfile()` which loads the raw text into a
  `ScrolledText` widget (`vriTk.py` lines 156–166, 266–283).
* **`.gitignore`** — Standard Python ignores plus two project-specific
  entries: `models/webcam.png` and `arrays/scan.png` (the runtime artefacts
  of the webcam capture and array-scan features).

### 3.3 Python compatibility

Both top-level scripts and `util_tk.py` open with a `try/except` that
imports the Python 2.x names (`Tkinter`, `tkFont`, `tkFileDialog`, etc.)
first and falls through to the Python 3.x `tkinter.*` names on
`Exception` (`vriTk.py` lines 87–103, `vriTkDemo.py` lines 106–122,
`Imports/util_tk.py` lines 46–55). The README declares "works with both
Python 2.7.x and 3.x" (`README.md` line 19).

A dated Python 3 compatibility shim survives in
`vriCalc.calc_elevation_curve()`:

```python
telescope = np.bytes_(telescope).decode("utf-8")  # Python 3 fix
```
(`Imports/vriCalc.py` line 811)

…and in the elevation-curve plot in `vriTk.py` line 459:
`label=e.decode("utf-8")`. These suggest the code stores telescope
names in `np.recarray` byte-string columns and decodes lazily — see §7.1.

### 3.4 Platform-specific tweaks

On macOS the GUI hard-codes the `TFrame` background colour to `#ececec`
and font size to 12 pt, and on every other platform it falls back to the
default Tk colour and 10 pt (`vriTk.py` lines 1851–1865). On Windows
10, `PlotFrame` builds the matplotlib `Figure` *without* setting
`facecolor`, working around a documented MPL ValueError on that
platform (`vriTk.py` lines 1597–1600, also added in commit `bd30450`).

## 4. How to run

There is no installable `console_scripts` entry point — the user runs a
script directly. From within `friendlyVRI/`:

```bash
python vriTk.py        # the canonical GUI
# or
python vriTkDemo.py    # the alternate notebook-tab GUI
```

The import block uses relative paths (`from Imports.util_tk import *`,
`from Imports.vriCalc import *`, `from Imports.util_scan import *`) so
the CWD must be the `friendlyVRI/` directory. The application also
loads `docs/HELP.txt`, `docs/ABOUT.txt`, `Imports/folder_small.gif`
and `Imports/camera_small.gif` by relative path (`vriTk.py` lines
158–163, 1095, 1103) — running from elsewhere will silently break menu
items or icons.

There is no command-line argument parsing of any kind. The `if
__name__ == "__main__":` block (`vriTk.py` lines 1847–1889) only:

1. Creates the `tk.Tk()` root.
2. Sets platform-conditional fonts/colours.
3. Tries the `tk_getOpenFile -foobarbaz` Linux trick to hide dotfiles
   in the file dialog (`vriTk.py` lines 1869–1881; comment cites
   `https://mail.python.org/pipermail/tkinter-discuss/2015-August/003762.html`).
4. Constructs `App(root, bgColour)` and runs `root.mainloop()`.

| `vriTkDemo.py` | A single window with a **`ttk.Notebook`** containing five tabs: *(1) Choose Model Image, (2) Create New Telescope Array, (3) Select Array Configurations, (3) Do Observations, (4) View Results*. ### 5.2 Toolkit & event model

The framework is **stock Python `tkinter` / `ttk`** with a
**matplotlib FigureCanvasTkAgg** embedding for plots. There is
**no Qt, no GTK, no web component**.

The internal communication pattern is **virtual events**: child widgets
generate events such as `<<config_in_selected>>`,
`<<selection_changed>>`, `<<obsparm_changed>>`,
`<<pixscale_changed>>`, `<<plot_modFFT>>`, `<<plot_uvcoverage>>`,
`<<plot_elevation>>`, `<<do_observation>>`, `<<show_results>>`,
`<<load_model_image>>`, `<<show_scanwin>>`, `<<array_scanned>>`,
`<<plot_scalehist>>` (demo only), `<<model_selected>>` (demo only)
on the root window, and `App.__init__` binds each of them to a
dedicated handler method `_on_xxx(event)` (`vriTk.py` lines 227–249).
This keeps widget classes loosely coupled — they don't call into the
controller directly, they just `self.event_generate("<<...>>")`.

## 6. Public API and CLI

### 6.1 Headless API: `observationManager`

The `observationManager` class in `Imports/vriCalc.py` is the
*designed-for-reuse* entry point. The README points users at it for
"alternative interfaces" (`README.md` lines 56–58); `CALCULATIONS.md`
contains a complete worked example. Reproduced here verbatim from
`CALCULATIONS.md`:

```python
from Imports.vriCalc import observationManager
obsMan = observationManager(verbose=True, debug=True)
obsMan.get_available_arrays()

obsMan.select_array('VLA_A')
obsMan.select_array('VLA_B')
obsMan.select_array('VLA_C')
obsMan.select_array('VLA_D')
obsMan.get_selected_arrays()

obsMan.set_obs_parms(1420.0, 20.0)         # freq_MHz, dec_deg
obsMan.calc_uvcoverage()
obsMan.load_model_image("models/galaxy_lobes.png")
obsMan.set_pixscale(1.0)                   # arcsec
obsMan.invert_model()
obsMan.grid_uvcoverage()
obsMan.calc_beam()
obsMan.invert_observation()
```

#### Constructor

```python
observationManager(arrayDir="arrays", verbose=True, debug=True)
```

(`Imports/vriCalc.py` lines 100–181). Reads every `*.config` under
`arrayDir/` and stores them in an `OrderedDict` keyed by
`<telescope>_<config>`.

### 6.2 `antArray` class

`Imports/vriCalc.py` lines 824–984. A lightweight container populated
from a single `.config` file.

```python
ar = antArray("arrays/VLA_A.config")
ar.telescope, ar.config              # 'VLA', 'A'
ar.latitude_deg, ar.diameter_m       # 34.078745, 25.0
ar.eastArr_m, ar.northArr_m          # raw E, N offsets (float32)
ar.xArr_m, ar.yArr_m, ar.zArr_m      # rotated to Earth-centred coords
ar.Bx_m, ar.By_m, ar.Bz_m            # baselines (length nBase = N(N-1)/2)
ar.lBase_m                            # baseline lengths
ar.nAnt, ar.nBase
```

Internally `_load_arrayfile` (lines 871–956) parses key/value lines and
two-column `EAST,NORTH` lines using regular expressions:

```python
spaces        = re.compile('\s+')
commaAndSpaces= re.compile(',\s+')
comment       = re.compile('#.*')
quotes        = re.compile('\'[^\']*\'')
keyVal        = re.compile('^.+=.+')
twoCSVcols    = re.compile('^.+,.+')
```

Defaults if a key is missing: `telescope="UNKNOWN"`, `config="UNKNOWN"`,
`latitude_deg=20.0`, `diameter_m=22.0` (lines 922–931). Loading silently
fails (returns object with `.telescope is None`) for files with fewer
than two antennas (lines 940–941).

The Earth-centred conversion is the textbook latitude rotation:

```python
xArr_m = -northArr_m * sin(latitude_rad)
yArr_m =  eastArr_m
zArr_m =  northArr_m * cos(latitude_rad)
```
(lines 947–950). The comment at lines 943–946 notes that the
"distance-from-centre-of-Earth" terms cancel out when computing
*baseline differences*, justifying the simplification.

Baselines are computed as all unique unordered pairs:

```python
for i in range(nAnt-1):
    for j in range(i+1, nAnt):
        Bx[n] = xArr[j] - xArr[i]; By[n] = yArr[j] - yArr[i]; Bz[n] = zArr[j] - zArr[i]
        n += 1
lBase_m = sqrt(Bx**2 + By**2 + Bz**2)
```
(lines 962–984). Number of baselines is therefore `N(N-1)/2`.

## 7. Core algorithms

The simulation pipeline is the textbook two-element interferometer
formulation, expressed in terms of the equatorial baseline components
(Bx, By, Bz) and a "convolution-via-FFT" image-domain inversion. Each
step below cites the implementing function.

### 7.1 Antenna positions → baselines

* Inputs to a config file: per-antenna `(East_m, North_m)` plus
  `latitude_deg` and `diameter_m`.
* East/North are rotated into Earth-centred (X, Y, Z) by a rotation
  about the local east axis through angle `(90° − latitude)`
  (`Imports/vriCalc.py` lines 947–950, see §6.2 for the formulae).
* Baseline vectors `(Bx, By, Bz)` are antenna-pair differences in the
  Earth-centred frame (`_calc_baselines`, lines 958–984).

Speed of light is hard-coded:

```python
C = 2.99792458e8
```
(`Imports/vriCalc.py` line 82).

### 7.2 uv-coverage from earth rotation

Implemented in `observationManager.calc_uvcoverage()`
(`Imports/vriCalc.py` lines 390–498). Per selected array configuration:

1. Build the hour-angle vector from `haStart` to `haEnd`:
   ```python
   sampRate_hr = sampRate_s / 3600.0
   nSamps = int((haEnd - haStart)/sampRate_hr + 1)
   haArr_hr = np.linspace(haStart, haEnd, nSamps)
   haArr_rad = np.radians(haArr_hr * 15.0)
   ```
2. Mask out samples that fall below the horizon by computing the
   elevation curve via `calc_elevation_curve` and setting
   `haArr_rad[elArr_deg<=0] = np.nan`.
3. For each baseline `i` and each HA, compute (u, v) in metres using
   the standard expressions for an East-pointing baseline at declination
   `δ` and hour angle `H`:
   ```
   u_m = Bx*sin(H) + By*cos(H)
   v_m = -Bx*sin(δ)cos(H) + By*sin(δ)sin(H) + Bz*cos(δ)
   ```
   (lines 441–448). The third component (w) is *not* computed — fVRI
   assumes coplanar arrays, the very simplification called out in the
   README's caveats (`README.md` line 73).
4. Convert to wavelengths: `e["uArr_lam"] = u_m / lambda_m`, similarly
   for v.
5. Compute per-config min/max angular scale:
   ```python
   lArr_lam = sqrt(uArr_lam**2 + vArr_lam**2)
   scaleMin_deg = degrees(1.0 / nanmax(lArr_lam))
   scaleMax_deg = degrees(1.0 / nanmin(lArr_lam))
   priBeam_deg  = degrees(1.22 * lambda_m / diameter_m)
   ```
   (lines 458–462). Note: `priBeam_deg` is the *Airy first null*, not the
   FWHM.
6. Per-ensemble: `scaleMin_deg = min(per-config scaleMin)`,
   `scaleMax_deg = max(per-config scaleMax)`, and the "uv ranges" are the
   reciprocals of those scales in radians (lines 482–486).

### 7.3 Model FFT and Fourier-space pixel scales

`invert_model()` (`Imports/vriCalc.py` lines 566–606):

```python
modelFFTarr   = fft2(modelImgArr)
modelFFTarr   = fftshift(modelFFTarr)
pixScaleImg_lam = radians(pixScaleImg_asec/3600.0)
fftScale_lam     = 1.0 / pixScaleImg_lam            # half-width of FFT image in λ⁻¹
pixScaleFFTX_lam = 2.0 * fftScale_lam / nX          # pixel size in λ⁻¹, X
pixScaleFFTY_lam = 2.0 * fftScale_lam / nY          # pixel size in λ⁻¹, Y
```

The Fourier-domain grid is therefore *dictated by the input model*
(its size and pixel scale) — there is no separate uv grid size
parameter. This is also the basis of the README caveat that
"the sampling grid in the Fourier domain [is set] from the extent and
pixel spacing of the input image, which can result in under-sampled
synthesised beams and artefacts" (`README.md` lines 73–76).

### 7.4 Gridding

`grid_uvcoverage()` (`Imports/vriCalc.py` lines 608–668). For each
selected array, each (u,v) sample is mapped to its nearest pixel using

```python
u_pix  = ( u_lam + fftScale_lam) / pixScaleFFTX_lam
v_pix  = ( v_lam + fftScale_lam) / pixScaleFFTY_lam
u2_pix = (-u_lam + fftScale_lam) / pixScaleFFTX_lam
v2_pix = (-v_lam + fftScale_lam) / pixScaleFFTY_lam
```

The mask is set to 1 at both the (u, v) and the (-u, -v) pixel
(Hermitian conjugate — the visibility function of a real sky is
Hermitian), and `uvCntArr` is incremented at each. Out-of-grid samples
are silently dropped (the inner `try/except Exception: pass`).
The percentage of pixels populated is logged when `verbose=True`.

The final filtered FFT is

```python
obsFFTarr = modelFFTarr * uvMaskArr   # element-wise
```

Note: only **natural weighting** is implemented. Robust weighting is on
the TODO list (`TODO.txt` line 6: "Robust weighting calculation"; the
GUI's `robust` combobox only contains "None"; `vriTk.py` lines 1139–1141).

### 7.5 Synthesised beam

`calc_beam()` (`Imports/vriCalc.py` lines 670–694):

```python
beamArr = ifft2(uvMaskArr)
beamArr = ifftshift(beamArr)
```

i.e. the dirty beam (PSF) is the inverse FFT of the *binary uv mask*.

### 7.6 Dirty image

`invert_observation()` (`Imports/vriCalc.py` lines 696–723):

```python
obsImgArr = ifft2(ifftshift(obsFFTarr))
```

Note the asymmetry with `calc_beam`: the beam uses
`ifft2` *then* `ifftshift`; the dirty image uses `ifftshift` *then*
`ifft2`. Both are valid sequences for centred FFTs but they differ.
The GUI displays `np.abs(obsImgArr)` — the imaginary residual is
discarded (`vriTk.py` line 556).

### 7.7 Elevation curves

`calc_elevation_curve(telescope, haArr_hr=None)`
(`Imports/vriCalc.py` lines 802–821). Standard spherical-trig formula:

```
sin(el) = sin(lat)·sin(δ) + cos(lat)·cos(δ)·cos(H)
```

Negative elevations are clipped to 0. If `haArr_hr` is `None` it samples
600 points across ±12 h.

### 7.8 Webcam-based "scan an array" workflow

`Imports/util_scan.py` provides three functions:

| Function | Lines | Purpose |
|----------|-------|---------|
| `scan_to_pixcoords(imgName, eSize=41, threshold_sigma=3.0, minPix=100, cropX=640, cropY=480, flatImgName=None, ax=None)` | 47–124 | Open a PNG, optionally subtract a flat field, crop, perform a morphological grey-erosion + grey-dilation "opening" with a circular footprint of size `eSize` (`generate_footprint`), threshold at `median + threshold_sigma·std`, label connected components with `scipy.ndimage.label`, find centroids of islands with ≥ `minPix` pixels. |
| `centroid(data)` | 128–138 | Intensity-weighted centroid. |
| `generate_footprint(size)` | 142–147 | Boolean disk of given diameter for use as a structuring element. |
| `write_arrayfile(fileName, X_m, Y_m, Nx, Ny, scale_m, telescope, config, latitude_deg=-20.0, diameter_m=22.0)` | 151–167 | Convert pixel positions to physical metre offsets via `pixScale_m = scale_m/Nx`, recentre on `Nx/2, Ny/2`, and write a `key=value` + `E,N` `.config` file matching the format in §8.1. |

The full pipeline (in `vriTk.ArrayScanner`):

1. `cv2.VideoCapture(); cam.open(1)` (the *second* webcam — see commit
   `94e1dd4`), read 10 frames to let auto-exposure settle, keep the

2. Resize 50 %, write `arrays/scan.png`.
3. Pass through `scan_to_pixcoords`.
4. On `Save Array`: write `arrays/custom.config`, then send
   `<<array_scanned>>` so the controller hot-loads the new config via
   `obsManager._load_one_array("arrays/custom.config")` and removes the
   temp file (`vriTk.py` lines 589–604).

This feature only appears if `import cv2` succeeds.

## 10. Integration & extension points

Practical extension surfaces, in approximate order of how cleanly they
slot into existing code:

1. **Add a new array** — drop a new `.config` file in `arrays/` and the
   GUI will pick it up at start-up; nothing else to wire. The
   combination `<telescope>_<config>` must be unique.
2. **Add a new model** — drop a PNG/JPEG/etc. into `models/` and use
   the `Browse` button, or call `obsMan.load_model_image("path")`
   directly from Python. The `ImageBrowser` widget in the demo GUI will
   auto-discover any image in the directory.
3. **Use the back-end headlessly** — `from Imports.vriCalc import
   observationManager`. `observationManager` can run end-to-end without
   instantiating any Tk widgets. `numpy` and `Pillow` are the only hard
   requirements at that level.
4. **Write a different front-end** — every `_on_*` handler in `vriTk.App`
   is a thin shim around an `obsManager` method, so a Qt or Jupyter
   front-end can be built by replacing those handlers.
5. **Replace gridding/weighting** — `grid_uvcoverage()` is ~40 lines
   and only consumes `arrsSelected[i]["uArr_lam"]`,
   `["vArr_lam"]`, `modelFFTarr.shape`, `pixScaleFFTX_lam`,
   `pixScaleFFTY_lam`, `fftScale_lam`. A robust-weighted variant could
   subclass `observationManager` and override this single method.
6. **Replace the dirty-image inversion** — `invert_observation()` is 4
   lines; trivially replaceable with a CLEAN loop or with a
   non-uniform-FFT path.
7. **Add custom widgets** — `Imports/util_tk.py`'s widget classes are
   self-contained Tk reusables (no project-specific state).

There is **no plugin system, no entry-points, no abstract base classes,
no event hooks beyond the Tk virtual events**. Extension is by editing
the source.

## 11. Notable internals & gotchas

* **PIL Resampling API** — `ImageBrowser` uses
  `Image.Resampling.LANCZOS` (Pillow ≥ 9). Older Pillow versions used
  `Image.LANCZOS`; running on a stale Pillow will raise
  `AttributeError`. Commit `522ae57 Updated to newest version of PIL`
  applied this fix.
* **Coplanar-array assumption** — the (u, v) calculation in
  `calc_uvcoverage` does not compute a `w` term. For VLBI-scale arrays
  this is a non-trivial limitation.
* **Half-power beam width** — `priBeam_deg` is computed as
  `1.22·λ/D` (degrees), which is the radius to the *first Airy null*,
  not the FWHM. The README and TODO refer to it as the primary-beam
  estimate; if you compare to other tools, watch the factor.
* **Decode dance** — `calc_elevation_curve` does
  `np.bytes_(telescope).decode("utf-8")` to handle both Python-2 strings
  and Python-3 byte-strings stored in numpy structured arrays
  (`Imports/vriCalc.py` line 811).
* **Demo file has a stale Python-2 method call** — `vriTkDemo.py` line
  618 has `self.obsManager.arrsAvailable.values()[-1]` which works on
  Python 2 but raises `TypeError` on Python 3 (dict_values is not
  subscriptable). The production `vriTk.py` line 597 wraps it with
  `list(...)` correctly. The demo GUI is therefore not a clean Python-3
  drop-in for the array-scanner workflow.
* **`tk_getOpenFile -foobarbaz` hack** — On Linux, hidden files appear
  by default in `tk_getOpenFile`. The two-line trick at
  `vriTk.py` 1869–1881 forces them off; the comment in source links the
  exact mailing-list message it was lifted from.
* **`ScatterPlot._scale_data_axes`** clamps zero ranges to 1, so a
  degenerate single-antenna array doesn't crash the antenna-layout
  preview.
* **Status checkbox auto-enabling** — `StatusFrame.set_state` enables
  the `Calculate & Plot uv-coverage` button only if state[0] (Array) is
  green; the `Model FFT` button only if state[1] (Model) is green; and
  `Do Observation` only if both are green. Buttons are otherwise
  greyed out — this is the only place state flags drive UI affordances
  (`vriTk.py` lines 1352–1364).
* **`PlotFrame.clear_by_state`** — implements a manual cascade: an
  upstream invalidation (e.g. a new array config) clears every
  downstream plot panel that is currently populated, but only those
  (lines 1785–1836). This avoids redrawing six axes on every keystroke.
* **`EmailPoster`** — is dead code; not instantiated and the email
  handler is `print("EMAIL!")`. It looks like leftover machinery for an
  outreach kiosk version of the app.
