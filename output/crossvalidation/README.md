# Cross-implementation validation records

This directory holds the Tier-2 cross-validation evidence that
`Tier7JonesSciencePlan.md` Section 29 requires: a comparison of RadioSim's
visibilities against an **independent simulator**, recorded rather than gated.

It is not the whole of RadioSim's validation. Section 29's Tier-1 evidence —
comparisons against published closed forms written out in the test body, and
against libraries already in the gating environment — lives in the ordinary
unit suite and runs in every gate. This directory exists because a second
*simulator* cannot be a gate: it is not in the locked default environment.

## What is here

| File | Contents |
| --- | --- |
| `2026-08-02-pyuvsim-1.4.0.json` | RadioSim vs `pyuvsim 1.4.0`, measured on `osx-arm64`, 2026-08-02 |
| `2026-08-08-pyuvsim-1.4.0.json` | SCI-006 east-X rerun: direct Q/U, explicit V mapping, and refitted SCI-007 residual |
| `2026-08-11-pyuvsim-1.4.0-sci007.json` | SCI-007 schema 1.2.0: public and exact source-time frame grids, correction controls, fixture/IERS provenance, and deeply pinned residuals |
| `<date>-sci005-efield-pyuvsim-1.4.0.json` | SCI-005 Stage-3 full-efield comparison, schema `radiosim.sci005.stage3-crossvalidation.v1` — generated by the `E3` campaign, not by `S3` |

## Reproducing it

The reference lives in an optional pixi environment that no CI job builds and
no gate runs:

```bash
pixi install --locked -e crossval
pixi run --environment crossval -- \
    python -m pytest tests/crossvalidation/ -m crossval
```

Set ``RADIOSIM_CROSSVAL_METRICS=1`` and add ``-s`` to emit the two measured
case records as machine-readable JSON, matching the dated artifact.

The SCI-007 record is a stricter evidence successor. It was generated from the
clean source commit
`9b50805cf9fe32124800d1e3946a87e3911c376b`, before the artifact existed, with:

```bash
pixi run --environment crossval -- python \
    tools/wp6_sci007_evidence.py generate \
    --approved-source-sha 9b50805cf9fe32124800d1e3946a87e3911c376b \
    --output output/crossvalidation/2026-08-11-pyuvsim-1.4.0-sci007.json
```

The generator deliberately refuses to overwrite the committed record. Validate
its exact bytes and full schema from any standard environment with:

```bash
pixi run python tools/wp6_sci007_evidence.py validate \
    --approved-source-sha 9b50805cf9fe32124800d1e3946a87e3911c376b \
    --artifact-sha256 3a441ad606f365ac4110e30d9d8c2f3d7f5ea91c481aa70488dea72487e570ba \
    --input output/crossvalidation/2026-08-11-pyuvsim-1.4.0-sci007.json
```

## The SCI-005 Stage-3 record

`docs/development/sci005_beam_physics_plan.md` Sections 5.5 and 8.1 govern the
Stage-3 full-efield comparison. Its artifact is a different, strictly validated
seventeen-key document whose `schema_version` is
`radiosim.sci005.stage3-crossvalidation.v1`, and it is generated once from a
globally clean `HEAD == S3` in the optional `crossval` environment with:

```bash
pixi run --environment crossval -- python \
    tools/sci005_stage3_crossvalidation.py generate \
    --approved-source-sha <40hex-S3> \
    --output <absolute-temporary-artifact.json>
```

`--output` must be an absolute path **outside** repository root: the only
admissible way for those bytes to enter this directory is the evidence
transaction in `tools/sci005_stage_evidence.py`, which re-checks the schema
literal, `source_sha == S3`, the pinned reference versions, and every input
digest before it writes. Validate the committed record's exact bytes and full
schema from any standard environment with:

```bash
pixi run python tools/sci005_stage3_crossvalidation.py validate \
    --approved-source-sha <40hex-S3> \
    --artifact-sha256 <64hex> \
    --input output/crossvalidation/<date>-sci005-efield-pyuvsim-1.4.0.json
```

Two properties of that comparison are frozen, because measurement showed the
harness could otherwise report a difference it had itself created. pyuvsim's
`BeamList` is constructed with `spline_interp_opts` `{"kx": 1, "ky": 1, "s": 0}`
to match RadioSim's pinned bilinear — without that equalization the order
mismatch alone contributes `1.27e-1` and the run is not evidence — and no
trace-invariance expectation is retained, because the invariance holds only
when the coherency is proportional to the identity or the Jones matrix is
proportional to a unitary, and a full-efield `E` is neither. Bounds are
asserted only on the mechanism-free quantities, `I` and `V`; the `Q`/`U`-carrying
correlations disagree through the recorded `pyradiosky` local-frame linear
mirror and are retained as a structured, mechanism-explained open disagreement
with its two line citations and its measured transfer-solve residual. Nothing
here licenses the sentence "pyuvsim is wrong".

**Naming.** This record's basename deliberately departs from the
`<date>-pyuvsim-<version>` pattern the three older files use: Section 7.4
freezes it as `<date>-sci005-efield-pyuvsim-1.4.0.json`, and the standard
suite's `output/crossvalidation/*.json` walker carries exactly one bounded
carve-out for it, mirroring the SCI-007 one.

The `crossval` environment shares a solve group with `default`, so it is
`default` plus exactly one package — `pyuvsim-1.4.0-py3-none-any.whl` — on all
three locked platforms. That is deliberate: a comparison run against a
differently resolved stack would be evidence about a different build of
RadioSim.

`pyuvsim 1.4.0` is pinned, not floated. It is the newest release whose metadata
is satisfiable against this repository's `pyuvdata ==3.2.1`; `1.4.2` requires
`pyuvdata >=3.2.3`.

## What may be claimed from it

Only what a named case measured, at the tolerance it measured. The record's own
`claims_not_licensed_by_this_record` field lists the sentences this evidence
does **not** support, and `unresolved` lists the two questions the comparison
opened rather than closed. Section 29.2 of the plan is the governing rule:
"validated against pyuvsim" is a forbidden claim unless it names the quantity
and the tolerance.
